# 발표 자료 — 백엔드 상세 정리 (안심 계약 가디언)

> PPT 슬라이드용 상세본. 진행상황·문제해결·향후계획 중심.
> 담당자 칸의 `[이름]`은 팀에서 채우세요.

---

## 1) 백엔드 한 줄 소개

**"전세 계약서 사진 한 장 → AI가 위험도 분석 → 즉시 행동 가이드 제공"**

자립준비청년을 전세사기로부터 보호하기 위한 분석 백엔드.
계약서 OCR → 개인정보 마스킹 → 공공데이터 검증 → AI 독소조항 탐지까지 **4단계 자동 파이프라인**으로 구성.

---

## 2) 전체 처리 흐름 (4단계 파이프라인)

```
[1단계] 이미지 분석
   계약서 사진 업로드 → CLOVA OCR로 텍스트 추출
   → 개인정보 마스킹(이름·주소·주민번호·전화)
   → 전세보증금 자동 추출 → Redis 세션 발급(UUID)
        ↓
[2단계] 주소 검증
   도로명주소 공공API로 주소 유효성 확인
   → 도로명주소·지번·우편번호·법정동코드(bjd_code) 확보
        ↓
[3단계] 건물 정보 조회
   건축물대장 API로 건물 등기·건축연도 확인
   → 국토부 실거래가로 매매가 조회 → 전세가율 계산
        ↓
[4단계] AI 리스크 분석
   RAG(법령 46개 검색) + GPT로 독소조항 탐지
   → 위험점수(0~100)·등급(safe/caution/danger)·행동가이드 생성
   → 분석 완료 후 개인정보 매핑테이블 즉시 파기
```

- 단계 간 데이터는 **Redis 세션(30분 TTL)**으로 연결, UUID v4로 식별
- 각 단계는 독립 API라 Flutter가 화면별로 호출

## 3) 기술 스택 & 선택 이유

| 분류 | 기술 | 선택 이유 |
|---|---|---|
| 웹 프레임워크 | FastAPI + Uvicorn | 비동기 처리, 자동 API 문서(Swagger), 타입 검증 |
| OCR | CLOVA OCR | 한글 계약서 인식률 우수 |
| 개인정보 마스킹 | KLUE-NER(KoELECTRA) + 정규식 | 이름·기관은 AI, 주민번호·전화는 정규식 이중 처리 |
| 벡터검색(RAG) | ChromaDB + KURE-v1 | 한국어 법률 문장 임베딩 특화 |
| LLM | GPT-4o / gpt-4o-mini | 환경변수로 토글(테스트 mini, 발표 4o) |
| 세션 | Redis | 인메모리·빠름·TTL 자동만료(개인정보 보호) |
| 공공 API | 도로명주소·건축물대장·국토부 실거래가 | 무료 공공데이터 활용 |

## 5) 진행 상황 상세 (✅ 완료된 것 — 근거 포함)

- **4단계 파이프라인 전체 연결 검증** — 실서버 E2E 호출에서 1~4단계 모두 정상 응답(HTTP 200) 확인
- **OCR** — 실제 계약서 이미지에서 텍스트 추출 성공
- **마스킹** — 임대인/임차인 이름·주소가 `[PERSON_xxx]`·`[ADDR_xxx]`로 치환됨 확인. 주민번호·전화는 정규식으로 추가 마스킹
- **전세금 추출** — 실서버 OCR 텍스트에서 `250,000,000원` 정확히 추출 (한글 금액·콤마·단위 모두 인식)
- **주소 검증** — 도로명주소 정제 + 법정동코드(예: `1168010100`) 정상 확보
- **RAG** — 법령·표준계약서·판례 46개를 벡터DB에 임베딩, 계약서와 유사 조항 검색 + 강행규정 위반 여부(`is_legal_basis`) 분류 반영
- **리스크 스코어링(규칙기반)** — 전세가율 구간별 감점, 미등기 시 0점·danger 강제, 독소조항 심각도별 감점
- **헬스체크 실측** — 외부 API(OCR·주소·건물·OpenAI)와 내부 DB 실제 연결 상태 점검
- **API 명세 정합성** — 실서버 기준으로 명세서 재정리(`docs/api_spec.md`), Flutter 연동용 제공

## 6) 문제 해결 사례 (트러블슈팅) — 발표 강조 포인트

> 테스트 과정에서 발견하고 고친 실제 사례. "검증을 통해 품질을 끌어올렸다"는 스토리.

| 발견한 문제 | 원인 | 해결 |
|---|---|---|
| **전세금이 항상 "정보 없음"** | 추출 로직이 아라비아 숫자(`2억5천`)만 인식, 실제 계약서의 한글(`이억오천만원`)·콤마(`250,000,000원`) 표기를 못 읽음 | 한글 숫자 환산기 + 콤마 파싱 추가, "보증금/전세" 키워드 근처 금액 우선 채택 |
| **RAG 법적근거 분류가 항상 false** | 분류값(`is_legal_basis`)이 벡터DB 메타데이터에 저장 안 됨 | 임베딩·검색 양쪽에 분류값 반영 |
| **GPT 실패가 "안전"으로 둔갑** | GPT 호출 실패 시 빈 결과 반환 → 위험한 계약이 100점 safe로 표시 | 실패 시 `502 AI_MODULE_ERROR`로 명확히 노출, 코드펜스 응답 파싱 보강 |
| **미등기인데 점수 70점** | 미등기 시 30점만 감점 | 미등기는 점수 0점·danger 강제(소유권 확인 불가 = 최악 위험) |
| **에러코드가 명세서와 불일치** | 일부 엔드포인트가 다른 코드/예외 사용 | 명세서 기준으로 통일(`INVALID_SESSION` 등), 예외 처리 일원화 |

## 7) 핵심 차별점

1. **Privacy-First 설계** — GPT에 실명·주소 절대 미전달(마스킹 텍스트만), 분석 후 매핑테이블 즉시 파기, 계약서 이미지 서버 미저장, 세션 30분 자동만료
2. **법적 근거 분류(`is_legal_basis`)** — 위험 조항을 "강행규정 위반(동의해도 무효)" vs "개인 체크 권장"으로 구분 → 사용자가 우선순위 판단 가능
3. **미등기 강제 차단** — 소유권 확인 불가 시 점수 무관 0점·danger 고정
4. **자립준비청년 특화** — 외부 API 없이 내부 DB로 지역별 자립지원 전담기관 자동 안내(법정동코드 매칭)
5. **RAG 근거 기반 판단** — 주임법·표준계약서·전세사기 판례 46개를 검색해 GPT 판단의 근거로 제공(환각 감소)
